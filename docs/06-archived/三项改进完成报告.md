### 1. 添加 Graceful Degradation 指标 ✅

**文件**: `middleware/degradation.go`

**改进内容**:
- 添加了完整的 Prometheus metrics 支持
- 新增 8 个 metrics 指标：
  - `degradation_level` - 当前降级级别
  - `degradation_active` - 是否正在降级
  - `degradation_events_total` - 事件处理统计（processed/dropped/delayed）
  - `degradation_triggers_total` - 降级触发原因统计
  - `degradation_cpu_usage_percent` - CPU 使用率
  - `degradation_memory_usage_percent` - 内存使用率
  - `degradation_goroutines_total` - Goroutine 数量
  - `degradation_recoveries_total` - 降级恢复统计

**使用示例**:
```go
// 创建降级控制器
deg := middleware.NewAdaptiveDegradation(middleware.DegradationConfig{
    CPUThreshold:    80.0,
    MemoryThreshold: 85.0,
    Strategy: middleware.DegradationDrop,
})

// 启动监控
go deg.StartMonitor(context.Background())

// 使用中间件
engine.Use(deg.Middleware())

// Prometheus metrics 会自动更新
// 可以通过 /metrics 端点暴露
```

**Prometheus 查询示例**:
```promql
# 当前降级级别
remilia_degradation_level

# 降级是否激活
remilia_degradation_active

# 事件处理速率
rate(remilia_degradation_events_total[5m])

# 丢弃率
rate(remilia_degradation_events_total{action="dropped"}[5m]) / 
rate(remilia_degradation_events_total[5m])

# CPU 使用率趋势
remilia_degradation_cpu_usage_percent

# 降级触发原因分布
sum by (reason) (remilia_degradation_triggers_total)
```

### 3. 添加分布式追踪采样策略 ✅

**文件**: 
- `infra/tracing/adaptive_sampler.go`（新文件）
- `infra/tracing/tracing.go`（修改）

**新增功能**:

#### AdaptiveSampler - 自适应采样器

**特性**:
- 根据错误率动态调整采样率
- 始终采样错误 span（可配置）
- 支持最小/最大采样率限制
- 自动监控和调整

**配置选项**:
```go
type AdaptiveSamplerConfig struct {
    BaseSamplingRate      float64       // 基础采样率 (0.1 = 10%)
    MinSamplingRate       float64       // 最小采样率 (0.01 = 1%)
    MaxSamplingRate       float64       // 最大采样率 (1.0 = 100%)
    ErrorThreshold        float64       // 错误率阈值 (0.05 = 5%)
    HighErrorSamplingRate float64       // 高错误率时的采样率 (0.5 = 50%)
    AdjustInterval        time.Duration // 调整间隔 (1分钟)
    AlwaysSampleErrors    bool          // 是否始终采样错误
}
```

**工作原理**:
1. 正常情况：使用基础采样率（如 10%）
2. 错误率超过阈值：自动提高采样率（如 50%）
3. 错误 span：始终采样（100%）
4. 定期调整：每分钟检查并调整采样率

**使用示例**:

##### 方式 1: 使用默认配置
```go
provider, err := tracing.NewProvider(tracing.Config{
    Enabled:             true,
    ServiceName:         "my-bot",
    Exporter:            "otlp",
    Endpoint:            "http://localhost:4318",
    SamplingRate:        0.1, // 10% 基础采样率
    UseAdaptiveSampling: true, // 启用自适应采样
})
if err != nil {
    return err
}
defer provider.Shutdown(context.Background())

// 启动监控协程
go provider.StartAdaptiveMonitor(context.Background())
```

##### 方式 2: 自定义配置
```go
adaptiveConfig := tracing.AdaptiveSamplerConfig{
    BaseSamplingRate:      0.1,  // 10% 基础采样
    MinSamplingRate:       0.01, // 最低 1%
    MaxSamplingRate:       0.8,  // 最高 80%
    ErrorThreshold:        0.03, // 3% 错误率阈值
    HighErrorSamplingRate: 0.6,  // 高错误时 60% 采样
    AdjustInterval:        2 * time.Minute,
    AlwaysSampleErrors:    true,
}

provider, err := tracing.NewProvider(tracing.Config{
    Enabled:               true,
    ServiceName:           "my-bot",
    Exporter:              "otlp",
    Endpoint:              "http://localhost:4318",
    SamplingRate:          0.1,
    UseAdaptiveSampling:   true,
    AdaptiveSamplerConfig: &adaptiveConfig,
})
```

##### 获取采样统计
```go
// 获取当前采样统计
stats := provider.GetSamplingStats()
if stats != nil {
    log.Printf("Total Spans: %d", stats.TotalSpans)
    log.Printf("Error Spans: %d", stats.ErrorSpans)
    log.Printf("Error Rate: %.2f%%", stats.ErrorRate * 100)
    log.Printf("Current Rate: %.2f%%", stats.CurrentSamplingRate * 100)
}
```

**收益**:
- **成本优化**: 正常时低采样率，减少存储成本
- **问题追踪**: 错误时高采样率，捕获更多trace
- **灵活性**: 自动适应系统状态
- **全面性**: 始终采样错误，不遗漏问题

**场景示例**:

| 场景 | 错误率 | 采样率 | 说明 |
|------|--------|--------|------|
| 正常运行 | 1% | 10% | 使用基础采样率 |
| 出现问题 | 8% | 50% | 自动提高采样率 |
| 严重故障 | 20% | 50% | 保持高采样率 |
| 恢复正常 | 2% | 10% | 恢复基础采样率 |
| 错误请求 | - | 100% | 始终采样错误 |
