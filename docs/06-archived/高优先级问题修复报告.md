## ✅ 问题 1：AdaptiveRateLimiter 信号量调整竞态条件

### 问题描述
原实现在 `adjustLimit` 方法中直接替换 `sema` channel，可能导致：
- 关闭旧 channel 导致等待的 goroutine 收到零值
- 令牌迁移过程中丢失正在使用的令牌
- 并发请求获得不正确的许可

### 原代码
```go
type AdaptiveRateLimiter struct {
    // ...
    sema chan struct{}  // 使用 channel 作为信号量
}

func (arl *AdaptiveRateLimiter) adjustLimit(newLimit int32) {
    newSema := make(chan struct{}, newLimit)
    // 迁移令牌
    currentLoad := int32(len(arl.sema))
    for i := int32(0); i < currentLoad && i < newLimit; i++ {
        newSema <- struct{}{}
    }
    arl.sema = newSema  // 直接替换 channel
}
```

### 修复方案
使用原子计数器代替 channel 信号量，避免 channel 替换的竞态问题。

### 修复后代码
```go
type AdaptiveRateLimiter struct {
    // ...
    // 移除 sema channel
    maxConcurrency atomic.Int32  // 使用原子变量
    currentLoad    atomic.Int32  // 当前负载
}

func (arl *AdaptiveRateLimiter) Middleware() eventctx.Middleware {
    return func(next eventctx.Handler) eventctx.Handler {
        return func(ctx *eventctx.Context) error {
            limit := arl.maxConcurrency.Load()
            
            // 使用 CAS 循环获取令牌
            const maxRetries = 1000
            for retry := 0; retry < maxRetries; retry++ {
                current := arl.currentLoad.Load()
                if current >= limit {
                    // 超过限制
                    return fmt.Errorf("rate limit exceeded")
                }
                
                if arl.currentLoad.CompareAndSwap(current, current+1) {
                    break  // 成功获取令牌
                }
            }
            
            defer func() {
                arl.currentLoad.Add(-1)  // 释放令牌
            }()
            
            return next(ctx)
        }
    }
}

func (arl *AdaptiveRateLimiter) adjustLimit(newLimit int32) {
    arl.maxConcurrency.Swap(newLimit)  // 原子更新限制
}
```

### 修复效果
- ✅ 消除了 channel 替换导致的竞态条件
- ✅ 限制调整立即生效，无需替换底层数据结构
- ✅ 使用 CAS 循环确保原子性，添加重试次数限制避免无限循环
- ✅ 令牌的获取和释放完全通过原子操作，保证一致性

### 文件修改
- `E:\project\Go\remilia\middleware\adaptive.go`
  - 移除 `sema chan struct{}` 字段
  - 修改 `Middleware()` 方法使用原子计数器
  - 简化 `adjustLimit()` 方法

## ✅ 问题 2：WebhookServerAdapter Goroutine 泄漏风险

### 问题描述
原实现中，如果 HTTP 服务器启动失败，worker goroutines 可能继续运行，导致资源泄漏。

### 原代码
```go
func (a *WebhookServerAdapter) Start(ctx context.Context, handler func(*dto.Payload)) error {
    // 启动 workers...
    
    // 启动 HTTP 服务器
    a.wg.Go(func() {
        if err := a.server.ListenAndServe(); err != nil {
            logger.Error(err)
        }
    })
    
    return nil  // 立即返回，不检查服务器是否启动成功
}
```

### 修复方案
添加服务器启动失败的检测和清理逻辑。

### 修复后代码
```go
func (a *WebhookServerAdapter) Start(ctx context.Context, handler func(*dto.Payload)) error {
    // ... 启动 workers ...
    
    // 启动 HTTP 服务器，使用 error channel 检测失败
    serverErrCh := make(chan error, 1)
    a.wg.Add(1)
    go func() {
        defer a.wg.Done()
        if err := a.server.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
            logger.WithError(err).Error("[WebhookServerAdapter] HTTP server error")
            serverErrCh <- err
            // HTTP 服务器启动失败，取消所有 workers
            a.cancel()
        }
    }()
    
    // 检查服务器是否立即失败（例如端口被占用）
    select {
    case err := <-serverErrCh:
        // 服务器启动失败，等待所有 workers 清理
        logger.WithError(err).Error("[WebhookServerAdapter] Server failed to start, cleaning up workers")
        a.wg.Wait()
        a.mu.Lock()
        a.running = false
        a.mu.Unlock()
        return fmt.Errorf("failed to start HTTP server: %w", err)
    case <-time.After(100 * time.Millisecond):
        // 服务器启动成功（没有立即报错）
        logger.Info("[WebhookServerAdapter] Started successfully")
        return nil
    }
}
```

### 修复效果
- ✅ 检测 HTTP 服务器启动失败
- ✅ 启动失败时自动取消所有 workers
- ✅ 等待所有 goroutines 清理完成后才返回
- ✅ 防止 goroutine 泄漏

### 文件修改
- `E:\project\Go\remilia\webhook_adapter.go`
  - 修改 `Start()` 方法添加错误检测和清理逻辑

## ✅ 问题 3：CircuitBreaker 半开状态竞态条件

### 问题描述
原实现在半开状态超时转换时缺少锁保护，CAS 循环没有限制重试次数。

### 原代码
```go
func (cb *CircuitBreaker) canExecute() error {
    state := cb.GetState()
    
    switch state {
    case StateHalfOpen:
        // 检查超时
        if time.Since(halfOpenStart) >= cb.config.HalfOpenTimeout {
            // 问题：多个 goroutine 可能同时执行此转换
            cb.state.Store(StateOpen)
            cb.lastFailure.Store(time.Now())
        }
        
        // CAS 循环没有限制
        for {
            current := cb.halfOpenReqs.Load()
            if current >= limit {
                return error
            }
            if cb.halfOpenReqs.CompareAndSwap(current, current+1) {
                return nil
            }
            // 无限重试
        }
    }
}
```

### 修复方案
1. 使用互斥锁保护状态转换
2. 添加 double-check 模式
3. 限制 CAS 循环的重试次数

### 修复后代码
```go
func (cb *CircuitBreaker) canExecute() error {
    for {
        state := cb.GetState()
        
        switch state {
        case StateHalfOpen:
            // 检查超时 - 使用锁保护状态转换
            halfOpenStart := cb.halfOpenStarted.Load().(time.Time)
            if !halfOpenStart.IsZero() && cb.config.HalfOpenTimeout > 0 {
                if time.Since(halfOpenStart) >= cb.config.HalfOpenTimeout {
                    cb.mu.Lock()
                    // Double-check 状态
                    if cb.GetState() == StateHalfOpen {
                        cb.state.Store(StateOpen)
                        cb.lastFailure.Store(time.Now())
                        if cb.config.OnStateChange != nil {
                            cb.config.OnStateChange(StateHalfOpen, StateOpen)
                        }
                        cb.mu.Unlock()
                        return fmt.Errorf("circuit breaker is open")
                    }
                    cb.mu.Unlock()
                    continue  // 状态已改变，重新检查
                }
            }
            
            // CAS 循环 - 限制重试次数
            for attempts := 0; attempts < 100; attempts++ {
                current := cb.halfOpenReqs.Load()
                if current >= int32(cb.config.HalfOpenMaxRequests) {
                    return fmt.Errorf("max requests exceeded")
                }
                if cb.halfOpenReqs.CompareAndSwap(current, current+1) {
                    return nil
                }
            }
            return fmt.Errorf("too many concurrent state transitions")
        }
    }
}
```

### 修复效果
- ✅ 状态转换添加互斥锁保护
- ✅ 使用 double-check 模式避免重复转换
- ✅ CAS 循环限制重试次数，防止 CPU 空转
- ✅ 提升熔断器可靠性

### 文件修改
- `E:\project\Go\remilia\middleware\circuitbreaker.go`
  - 修改 `canExecute()` 方法添加锁保护和重试次数限制
