## 🔧 修复详情

### 1. AdaptiveRateLimiter - 信号量调整竞态条件

**问题**：直接替换 channel 导致竞态条件

**修复**：
- 移除 `sema chan struct{}` 字段
- 使用 `atomic.Int32` 类型的 `currentLoad` 和 `maxConcurrency`
- 通过 CAS 循环获取/释放令牌（限制 1000 次重试）
- `adjustLimit()` 直接原子更新限制值

**文件改动**：
```
middleware/adaptive.go:
- 删除 sema 字段
- 修改 Middleware() 方法
- 简化 adjustLimit() 方法
```

---

### 2. WebhookServerAdapter - Goroutine 泄漏风险

**问题**：HTTP 服务器启动失败时 workers 继续运行

**修复**：
- 使用 error channel 检测服务器启动失败
- 启动失败时调用 `cancel()` 停止所有 workers  
- 等待所有 goroutines 清理完成后返回错误
- 添加 100ms 启动检测窗口

**文件改动**：
```
webhook_adapter.go:
- 修改 Start() 方法
- 添加 serverErrCh 错误通道
- 添加启动失败检测逻辑
```

---

### 3. CircuitBreaker - 半开状态竞态条件

**问题**：
- 半开状态超时转换缺少锁保护
- CAS 循环没有重试次数限制

**修复**：
- 状态转换使用 `mu.Lock()` 保护
- 添加 double-check 模式
- CAS 循环限制 100 次重试
- 重试失败返回明确错误

**文件改动**：
```
middleware/circuitbreaker.go:
- 修改 canExecute() 方法
- 添加锁保护的状态转换
- 限制 CAS 重试次数
```
