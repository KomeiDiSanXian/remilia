# v1.9.0 改进总结

## 概述

v1.9.0 版本继续提升系统的**可观测性和可维护性**，实现了三个中优先级特性：Context 对象池监控集成、临时 Matcher 自动清理和 HandlerError 堆栈信息。这些特性让系统更易于监控、调试和维护。

## 新增特性

### 1. Context 对象池监控集成

对象池现在支持自动监控，定期将统计信息导出到 Prometheus 指标。

#### 核心特性
- ✅ **自动监控**: `EnableMetrics()` 自动启动对象池监控
- ✅ **可配置间隔**: 自定义监控更新频率
- ✅ **Prometheus 集成**: 无缝集成到现有监控体系
- ✅ **零开销**: 只在启用指标时运行

#### 使用示例

```go
// 启用指标收集（自动启动对象池监控）
engine.EnableMetrics("my_bot")

// 或指定监控间隔
engine.EnableMetricsWithInterval("my_bot", 5*time.Second)

// 手动启动监控
mc := remilia.NewMetricsCollector("my_bot")
stop := mc.StartPoolMonitoring(10 * time.Second)
defer stop()
```

#### Prometheus 指标

```
# 对象池指标
remilia_pool_gets_total          # Get() 调用总数
remilia_pool_puts_total          # Put() 调用总数
remilia_pool_news_total          # 新建对象总数（未命中）
remilia_pool_hit_rate            # 命中率 (0-1)
remilia_pool_size                # 当前池大小
```

#### Grafana 仪表板示例

```promql
# 对象池命中率
remilia_pool_hit_rate{namespace="my_bot"}

# 每秒 Get 操作
rate(remilia_pool_gets_total{namespace="my_bot"}[1m])

# 命中率低于 80% 的告警
remilia_pool_hit_rate < 0.8
```

#### 文档
- 实现文件: `metrics.go` (新增 `StartPoolMonitoring` 方法)
- 测试文件: `metrics_pool_test.go`

### 2. 临时 Matcher 自动清理

临时 Matcher 现在默认自动清理，无需手动启动清理器。

#### 核心特性
- ✅ **默认启用**: `NewEngine()` 自动启动清理器
- ✅ **可配置间隔**: 默认 5 分钟，可自定义
- ✅ **可禁用**: 设置间隔为 0 即可禁用
- ✅ **无内存泄漏**: 自动清理过期的临时 Matcher

#### 使用示例

```go
// 创建引擎（自动启动清理器，5分钟间隔）
engine := remilia.NewEngine()

// 修改清理间隔
engine.SetTempMatcherCleanInterval(10 * time.Minute)

// 禁用自动清理
engine.SetTempMatcherCleanInterval(0)

// 获取当前间隔
interval := engine.GetTempMatcherCleanInterval()

// 添加临时 Matcher（会被自动清理）
engine.On(dto.C2CMessageCreate).
    SetTempWithTimeout(5 * time.Minute).
    Handle(func(ctx *remilia.Context) {
        // 5分钟后自动删除
    })
```

#### 配置建议

| 场景 | 推荐间隔 | 说明 |
|------|---------|------|
| 高频临时 Matcher | 1-2 分钟 | 快速释放内存 |
| 常规使用 | 5 分钟（默认） | 平衡性能和内存 |
| 低频临时 Matcher | 10-15 分钟 | 减少清理开销 |
| 无临时 Matcher | 0（禁用） | 完全禁用清理 |

#### 内存影响

```go
// 示例：1000 个临时 Matcher 的内存占用
// 假设每个 Matcher 约 1KB
// 总内存: 1000 * 1KB = 1MB

// 清理前
engine.GetMatcherCount() // 1000

// 清理后（过期的被删除）
engine.GetMatcherCount() // 0

// 释放的内存: ~1MB
```

#### 文档
- 实现文件: `engine.go` (修改 `NewEngine`, 新增 `SetTempMatcherCleanInterval`)
- 测试文件: `engine_auto_cleaner_test.go`

### 3. HandlerError 堆栈信息

HandlerError 现在支持捕获完整的堆栈信息，极大提升了调试效率。

#### 核心特性
- ✅ **按需启用**: 通过环境变量或 API 控制
- ✅ **自动过滤**: 过滤 runtime 和框架代码
- ✅ **JSON 序列化**: 堆栈信息可序列化
- ✅ **格式化输出**: 提供友好的堆栈格式化

#### 使用示例

##### 启用方式 1：环境变量

```bash
# Linux/Mac
export REMILIA_STACK_TRACE=true
./my_bot

# Windows
$env:REMILIA_STACK_TRACE="true"
.\my_bot.exe
```

##### 启用方式 2：代码

```go
import "github.com/KomeiDiSanXian/remilia"

func main() {
    // 启用堆栈跟踪
    remilia.EnableStackTrace(true)
    
    // ... 创建 bot
}
```

##### 错误处理

```go
engine.On(dto.C2CMessageCreate).HandleE(func(ctx *remilia.Context) error {
    return errors.New("something went wrong")
})

// 在中间件或错误处理中
func LogErrors() remilia.HandlerMiddleware {
    return func(next remilia.HandlerE) remilia.HandlerE {
        return func(ctx *remilia.Context) error {
            err := next(ctx)
            if err != nil {
                // 格式化输出堆栈信息
                logrus.Error(remilia.FormatHandlerError(err))
            }
            return err
        }
    }
}
```

##### 输出示例

#### 性能考虑

堆栈捕获会带来性能开销：


**建议**:
- ✅ 开发环境：启用堆栈跟踪
- ✅ 测试环境：启用堆栈跟踪
- ⚠️ 生产环境：按需启用（排查问题时）

#### API

```go

remilia.EnableStackTrace(false)

// 检查状态

```

```go
    "github.com/KomeiDiSanXian/remilia"
    "github.com/prometheus/client_golang/prometheus/promhttp"

    engine := remilia.NewEngine()

    }
    
    // 4. 暴露 Prometheus 指标
    http.Handle("/metrics", promhttp.Handler())
    go http.ListenAndServe(":9090", nil)
    
    // ... 启动 bot
}
```

### 2. 错误日志增强

```go
// 自定义日志中间件，输出完整错误信息
func EnhancedLogging() remilia.HandlerMiddleware {
    return func(next remilia.HandlerE) remilia.HandlerE {
        return func(ctx *remilia.Context) error {
            start := time.Now()
            err := next(ctx)
            
            if err != nil {
                // 使用格式化输出，包含堆栈
                logrus.WithFields(logrus.Fields{
                    "latency":    time.Since(start),
                    "event_type": ctx.GetEventType(),
                    "event_id":   ctx.GetEvent().ID,
                }).Error(remilia.FormatHandlerError(err))
            } else {
                logrus.WithFields(logrus.Fields{
                    "latency":    time.Since(start),
                    "event_type": ctx.GetEventType(),
                }).Info("handler succeeded")
            }
            
            return err
        }
    }
}

engine.Use(EnhancedLogging())
```

### 4. 生产环境堆栈控制

```go
// 动态控制堆栈跟踪
func setupStackTrace() {
    // 监听 USR1 信号，动态启用堆栈
    sigCh := make(chan os.Signal, 1)
    signal.Notify(sigCh, syscall.SIGUSR1, syscall.SIGUSR2)
    
    go func() {
        for sig := range sigCh {
            switch sig {
            case syscall.SIGUSR1:
                // 启用堆栈（用于临时调试）
                remilia.EnableStackTrace(true)
                log.Info("Stack trace enabled")
                
                // 10分钟后自动关闭
                time.AfterFunc(10*time.Minute, func() {
                    remilia.EnableStackTrace(false)
                    log.Info("Stack trace auto-disabled")
                })
                
            case syscall.SIGUSR2:
                // 立即禁用
                remilia.EnableStackTrace(false)
                log.Info("Stack trace disabled")
            }
        }
    }()
}

// 使用方式：
// kill -USR1 <pid>  # 启用堆栈跟踪
// kill -USR2 <pid>  # 禁用堆栈跟踪
```
