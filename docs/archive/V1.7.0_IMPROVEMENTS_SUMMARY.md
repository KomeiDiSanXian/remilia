## 📊 集成测试覆盖

### 1. 基础集成测试 (`integration_test.go`)

#### 生命周期测试
- **TestFullLifecycle**: 完整的 Bot 生命周期
  - 创建 Bot → 注册中间件 → 注册 Handler → 处理事件 → 关闭
  - 验证中间件和 Handler 都被正确执行

#### 优先级与执行顺序
- **TestMultipleMatchers**: 多个 Matcher 的优先级排序
  - 验证低数字 = 高优先级
  - 验证执行顺序正确

#### 中间件链
- **TestMiddlewareChain**: 中间件链执行顺序
  - 验证洋葱模型：before → handler → after
  - 验证多层中间件嵌套

#### 异步处理
- **TestAsyncHandlers**: 异步 Handler 测试
  - 使用 WithRetain 延长 Context 生命周期
  - 验证并发安全和引用计数

#### 批量处理
- **TestBatchProcessing**: 批量事件处理
  - 处理 100 个事件
  - 验证所有事件都被正确处理

#### Context 状态管理
- **TestContextStateManagement**: Context 状态共享
  - 中间件设置状态
  - Handler 读取状态
  - 验证状态传递正确

#### 临时 Matcher
- **TestTempMatcherLifecycle**: 临时 Matcher 生命周期
  - 设置最大使用次数
  - 验证自动删除机制

#### 去重功能
- **TestDedupMiddleware**: 去重中间件集成
  - 相同事件多次处理
  - 验证只执行一次

#### 错误处理
- **TestErrorHandling**: 错误传播流程
  - Handler 返回错误
  - 中间件捕获错误
  - 验证错误传递

#### 并发测试
- **TestConcurrentEventProcessing**: 并发事件处理
  - 50 个并发请求
  - 验证线程安全

#### 阻断机制
- **TestBlockingMatcher**: 阻断 Matcher
  - 第一个 Matcher 阻断
  - 验证后续 Matcher 不执行

#### Context 克隆
- **TestContextClone**: Context 克隆功能
  - 克隆 Context
  - 修改克隆不影响原始
  - 验证独立性

#### 优雅关闭
- **TestGracefulShutdown**: 优雅关闭测试
  - 长时间运行的 Handler
  - 验证等待完成
  - 验证超时控制

#### 混合事件类型
- **TestMixedEventTypes**: 多种事件类型处理
  - C2C、Group、Any Handler
  - 验证路由正确

### 2. 端到端测试 (`integration_e2e_test.go`)

#### 命令处理流程
- **TestE2ECommandProcessing**: 完整的命令处理
  - 用户发送命令
  - 解析参数
  - 执行 Handler

#### 状态传播
- **TestE2EStatePropagation**: 端到端状态传播
  - 中间件设置多个状态
  - Handler 读取所有状态

#### 重试机制
- **TestE2ERetryMiddleware**: 重试中间件测试
  - 前两次失败
  - 第三次成功
  - 验证重试次数

#### 超时控制
- **TestE2ETimeoutMiddleware**: 超时中间件测试
  - Handler 超时
  - 验证超时机制

#### 慢 Handler 检测
- **TestE2ESlowHandlerDetection**: 慢 Handler 检测
  - Handler 执行时间过长
  - 验证检测回调

#### 复杂工作流
- **TestE2EComplexWorkflow**: 复杂工作流测试
  - 日志 → 认证 → 去重 → 多个 Handler
  - 验证完整流程
  - 验证去重生效

#### 状态共享
- **TestE2EStateSharing**: 多中间件状态共享
  - 多个中间件设置状态
  - Handler 读取所有状态
  - 验证数据完整性

#### 错误传播
- **TestE2EErrorPropagation**: 错误在中间件链中传播
  - Handler 抛出错误
  - 多层中间件捕获
  - 验证传播顺序

#### 内存管理
- **TestE2EMemoryUsage**: 内存使用和对象池
  - 处理大量事件
  - 验证对象池工作正常

### 2. 测试模式

#### 集成测试模式
```go
func TestIntegration(t *testing.T) {
    // 1. 创建组件
    engine := remilia.NewEngine()
    
    // 2. 配置中间件和 Handler
    engine.Use(middleware.Dedup(filter))
    engine.OnC2C().HandleE(handler)
    
    // 3. 模拟真实场景
    event := &dto.Payload{...}
    ctx := remilia.NewContext(event, nil)
    engine.ProcessEvent(ctx)
    ctx.Release()
    
    // 4. 验证结果
    assert.True(t, expectedResult)
}
```

#### 端到端测试模式
```go
func TestE2EWorkflow(t *testing.T) {
    // 1. 完整的系统设置
    bot := remilia.New(&dto.BotInfo{...})
    
    // 2. 注册完整的中间件链
    bot.GetEngine().Use(
        middleware.Logging(),
        middleware.Auth(),
        middleware.Dedup(filter),
    )
    
    // 3. 注册业务 Handler
    bot.GetEngine().OnC2C().HandleE(businessHandler)
    
    // 4. 模拟用户操作
    simulateUserAction()
    
    // 5. 验证端到端结果
    assert.Equal(t, expected, actual)
    
    // 6. 清理
    bot.Shutdown(context.Background())
}
```
