### 1️⃣ #16 - 错误处理不统一 ✅

**问题描述:**
- 项目中存在多种错误处理方式（返回 error、打日志、panic、忽略）
- 调用者不知道如何处理错误
- 错误可能被悄悄吞掉
- 调试困难，缺少上下文信息

**解决方案:**
实现了统一的错误处理机制，包括：

#### 1. 预定义错误类型
```go
// errors_unified.go

var (
    ErrConfigInvalid       = errors.New("invalid configuration")
    ErrMatcherNotFound     = errors.New("matcher not found")
    ErrContextReleased     = errors.New("context already released")
    ErrEngineShutdown      = errors.New("engine is shutting down")
    ErrInvalidEventID      = errors.New("invalid event ID")
    ErrHandlerNotSet       = errors.New("handler not set")
    ErrRuleCompileFailed   = errors.New("rule compile failed")
    ErrDedupCacheFull      = errors.New("dedup cache full")
    ErrDeadLetterFailed    = errors.New("dead letter processing failed")
)
```

#### 2. 错误包装器
```go
type ErrorWrapper struct {
    Err     error  // 原始错误
    Message string // 错误消息
    Context string // 错误上下文
}

func (e *ErrorWrapper) Error() string {
    if e.Context != "" {
        return fmt.Sprintf("%s [context: %s]: %v", e.Message, e.Context, e.Err)
    }
    return fmt.Sprintf("%s: %v", e.Message, e.Err)
}

func (e *ErrorWrapper) Unwrap() error {
    return e.Err
}
```

#### 3. 错误包装函数
```go
// 简单包装
func WrapErrorf(err error, message string) error

// 带上下文包装
func WrapErrorWithContextf(err error, message, context string) error

// 类型检查
func IsErrorType(err, target error) bool
```

#### 4. 专用错误创建函数
```go
// 验证错误
func NewValidationError(field, reason string) error

// 配置错误
func NewConfigError(key, reason string) error

// 插件错误
func NewPluginError(pluginName, message string) error

// Panic 恢复
func RecoverError() error
```

**使用示例:**
```go
// 错误包装
err := doSomething()
if err != nil {
    return WrapErrorf(err, "failed to do something")
}

// 带上下文包装
err := queryDatabase(userID)
if err != nil {
    return WrapErrorWithContextf(err, "query failed", "user_id="+userID)
}

// 错误类型判断
if IsErrorType(err, ErrContextReleased) {
    // 处理 Context 已释放的情况
}

// Panic 恢复
defer func() {
    if err := RecoverError(); err != nil {
        log.Error("panic recovered:", err)
    }
}()
```

**代码实现:**
- `errors_unified.go`: ~150 行
- 完整的错误类型体系
- 支持错误链追踪
- 兼容 Go 1.13+ 错误处理

**测试覆盖:**
- `errors_unified_test.go`: 16 个测试用例
- 测试错误包装、解包、类型判断、panic 恢复等

**用户影响:**
- ✅ **一致性**: 统一的错误处理方式
- ✅ **可追踪**: 完整的错误上下文
- ✅ **易调试**: 清晰的错误信息
- ✅ **兼容性**: 兼容标准库 errors 包

### 2️⃣ #17 - 缺少结构化日志字段 ✅

**问题描述:**
- 日志格式不统一，难以解析和查询
- 缺少关键上下文（如 event_id, user_id, event_type）
- 日志分散，不利于监控和告警

**解决方案:**
实现了完整的结构化日志系统，包括：

#### 1. 统一的日志字段常量
```go
// logger_structured.go

const (
    // 组件相关
    LogFieldComponent = "component"
    LogFieldSource    = "source"

    // 事件相关
    LogFieldEventID   = "event_id"
    LogFieldEventType = "event_type"
    LogFieldUserID    = "user_id"
    LogFieldGuildID   = "guild_id"
    LogFieldChannelID = "channel_id"

    // 请求相关
    LogFieldRequestID = "request_id"
    LogFieldLatency   = "latency"
    LogFieldAttempt   = "attempt"

    // Matcher 相关
    LogFieldMatcher  = "matcher"
    LogFieldPriority = "priority"

    // Plugin 相关
    LogFieldPlugin = "plugin"

    // 错误相关
    LogFieldError      = "error"
    LogFieldErrorType  = "error_type"
    LogFieldStackTrace = "stack_trace"

    // 性能相关
    LogFieldCacheSize = "cache_size"
    LogFieldCacheHit  = "cache_hit"
    LogFieldQueueSize = "queue_size"

    // 其他
    LogFieldAction = "action"
    LogFieldStatus = "status"
    LogFieldReason = "reason"
)
```

#### 2. 结构化日志记录器
```go
type StructuredLogger struct {
    entry *logrus.Entry
}

// 创建日志记录器
func NewLogger(component string) *StructuredLogger

// 链式添加字段
func (l *StructuredLogger) WithContext(ctx *Context) *StructuredLogger
func (l *StructuredLogger) WithFields(fields logrus.Fields) *StructuredLogger
func (l *StructuredLogger) WithField(key string, value interface{}) *StructuredLogger
func (l *StructuredLogger) WithError(err error) *StructuredLogger
func (l *StructuredLogger) WithLatency(duration time.Duration) *StructuredLogger
func (l *StructuredLogger) WithMatcher(matcher *Matcher) *StructuredLogger
func (l *StructuredLogger) WithPlugin(pluginName string) *StructuredLogger
func (l *StructuredLogger) WithAction(action string) *StructuredLogger
func (l *StructuredLogger) WithStatus(status string) *StructuredLogger
```

#### 3. 全局日志实例（按组件分类）
```go
var (
    engineLogger     = NewLogger("engine")
    contextLogger    = NewLogger("context")
    matcherLogger    = NewLogger("matcher")
    pluginLogger     = NewLogger("plugin")
    middlewareLogger = NewLogger("middleware")
    botLogger        = NewLogger("bot")
    deadLetterLogger = NewLogger("deadletter")
)

// 获取器
func GetEngineLogger() *StructuredLogger
func GetContextLogger() *StructuredLogger
func GetMatcherLogger() *StructuredLogger
// ... 等等
```

**使用示例:**

#### 基本使用
```go
// 创建组件日志
logger := NewLogger("mycomponent")
logger.Info("component started")

// 输出: {"component":"mycomponent","level":"info","msg":"component started"}
```

#### 添加 Context 字段
```go
logger := GetEngineLogger()
logger.WithContext(ctx).Info("processing event")

// 输出: {
//   "component":"engine",
//   "event_id":"evt-123",
//   "event_type":"C2C_MESSAGE_CREATE",
//   "matcher":"plugin:test",
//   "priority":50,
//   "msg":"processing event"
// }
```

#### 链式调用
```go
logger := GetEngineLogger()
logger.
    WithContext(ctx).
    WithLatency(duration).
    WithAction("process").
    WithStatus("success").
    Info("event processed")

// 输出: {
//   "component":"engine",
//   "event_id":"evt-123",
//   "latency":125,
//   "action":"process",
//   "status":"success",
//   "msg":"event processed"
// }
```

#### 错误日志
```go
logger := GetEngineLogger()
logger.
    WithContext(ctx).
    WithError(err).
    Error("failed to process event")

// 输出: {
//   "component":"engine",
//   "event_id":"evt-123",
//   "error":"database connection failed",
//   "msg":"failed to process event"
// }
```

**代码实现:**
- `logger_structured.go`: ~250 行
- 完整的结构化日志 API
- 自动提取 Context 字段
- 支持链式调用

**测试覆盖:**
- `logger_structured_test.go`: 18 个测试用例
- 测试所有日志方法和字段提取

**用户影响:**
- ✅ **可查询**: 结构化字段便于 ElasticSearch/Loki 查询
- ✅ **可监控**: 统一字段便于配置告警规则
- ✅ **可追踪**: 自动包含事件 ID 和请求 ID
- ✅ **易用**: 链式 API，使用简单
- ✅ **性能**: 基于 logrus，高性能

## 📝 最佳实践

### 错误处理

#### ✅ 推荐做法
```go
// 1. 使用预定义错误类型
if engine.isShuttingDown {
    return ErrEngineShutdown
}

// 2. 包装错误保留上下文
err := database.Query(sql)
if err != nil {
    return WrapErrorf(err, "failed to query database")
}

// 3. 添加详细上下文
err := processUser(userID)
if err != nil {
    return WrapErrorWithContextf(err, "failed to process user", "user_id="+userID)
}

// 4. 检查错误类型
if IsErrorType(err, ErrContextReleased) {
    log.Warn("context already released, skipping")
    return nil
}
```

#### ❌ 避免做法
```go
// 不要忽略错误
_, _ = file.Write(data)

// 不要只打日志不返回
if err != nil {
    log.Error("error occurred")
    return nil // ❌ 错误被吞掉
}

// 不要在库代码中 panic
if config == nil {
    panic("config is nil") // ❌ 应该返回错误
}
```

### 结构化日志

#### ✅ 推荐做法
```go
// 1. 使用组件日志
logger := GetEngineLogger()

// 2. 添加 Context 字段
logger.WithContext(ctx).Info("processing event")

// 3. 添加性能指标
logger.
    WithContext(ctx).
    WithLatency(duration).
    WithAction("process").
    Info("event processed")

// 4. 错误日志包含上下文
logger.
    WithContext(ctx).
    WithError(err).
    Error("failed to process event")
```

#### ❌ 避免做法
```go
// 不要使用纯文本日志
logrus.Info("[Engine] Processing event evt-123") // ❌ 难以查询

// 不要手动拼接字段
logrus.WithField("msg", "event_id="+eventID) // ❌ 格式不统一

// 不要缺少上下文
logrus.Error("error occurred") // ❌ 缺少关键信息
```
