### 1️⃣ #1 - 全局单例 Engine 的风险 ✅

**问题描述:**
- 全局单例在测试时难以隔离，多个测试用例可能互相干扰
- 不支持多实例场景
- 全局状态难以管理和重置

**解决方案:**
```go
// 重命名为 defaultEngine
var defaultEngine = NewEngine()

// 提供新的 API
func GetDefaultEngine() *Engine {
    return defaultEngine
}

// 添加重置方法用于测试
func ResetDefaultEngine() {
    defaultEngine = NewEngine()
}

// 保留向后兼容（标记为废弃）
func GetGlobalEngine() *Engine {
    return defaultEngine
}
```

**代码修改:**
- `engine.go`: 重命名变量，添加新方法
- `bot.go`: 更新引用
- 所有测试文件: 更新引用

**测试:**

- 测试隔离、并发安全、Bot 集成

**用户影响:**
- **向后兼容**: 100%（GetGlobalEngine 仍可用）
- **新功能**: 测试可以使用 ResetDefaultEngine() 隔离

### 2️⃣ #3 - Engine 排序缓存失效问题 ✅

**问题描述:**
- 当 Matcher 的 Priority 在运行时被修改时，缓存不会失效
- `SetPriority` 方法没有通知 Engine 重建缓存
- 用户困惑："为什么修改优先级没用？"

**解决方案:**
```go
// matcher.go - 修改 SetPriority
func (m *Matcher) SetPriority(priority uint) *Matcher {
    if m.Priority != priority {
        m.Priority = priority
        if m.Engine != nil {
            m.Engine.invalidateSortedCache(m.EventType)
        }
    }
    return m
}

// engine.go - 添加失效方法
func (e *Engine) invalidateSortedCache(eventType dto.EventType) {
    e.mu.Lock()
    defer e.mu.Unlock()
    delete(e.sortedCache, eventType)
    if eventType != "" {
        delete(e.sortedCache, "")  // 也失效通用缓存
    }
}
```

**代码修改:**
- `matcher.go`: SetPriority 方法增强
- `engine.go`: 添加 invalidateSortedCache 方法

**测试:**
- `engine_priority_cache_test.go`: 8 个测试用例
- 测试缓存失效、优先级变化、批量处理

**用户影响:**
- **立即生效**: Priority 修改后立即生效
- **性能**: 仅在值变化时失效缓存（优化）

### 3️⃣ #5 - 临时 Matcher 内存泄漏风险 ✅

**问题描述:**
- 如果 matcher 从未被匹配到，将永远留在内存中
- 没有基于时间的过期机制
- 长期运行的 bot 可能积累大量未使用的临时 matcher

**解决方案:**
```go
// matcher.go - 添加时间字段
type Matcher struct {
    // ...existing fields...
    createdAt   time.Time
    expiresAt   time.Time
}

// 新增方法
func (m *Matcher) SetTempWithTimeout(timeout time.Duration) *Matcher {
    m.IsTemp = true
    m.createdAt = time.Now()
    m.expiresAt = m.createdAt.Add(timeout)
    return m
}

// engine.go - 添加清理器
func (e *Engine) StartTempMatcherCleaner(interval time.Duration) func() {
    ticker := time.NewTicker(interval)
    done := make(chan struct{})
    
    go func() {
        for {
            select {
            case <-ticker.C:
                e.cleanExpiredMatchers()
            case <-done:
                return
            }
        }
    }()
    
    return func() { close(done) }
}
```

**代码修改:**
- `matcher.go`: 添加时间字段和 SetTempWithTimeout
- `engine.go`: 添加 StartTempMatcherCleaner 和 cleanExpiredMatchers

**测试:**
- `engine_temp_matcher_test.go`: 14 个测试用例
- 测试超时清理、停止清理器、多个清理器

**用户影响:**
- **可选功能**: 需要手动启动清理器
- **防止泄漏**: 自动清理过期的临时 matcher

### 4️⃣ #7 - ProcessEventBatch 没有利用排序缓存 ✅

**问题描述:**
- `ProcessEvent` 使用了 `sortedCache`，但 `ProcessEventBatch` 没有
- 批量处理时 Matcher 执行顺序不一致
- Priority 在批量处理时不生效

**解决方案:**
```go
// engine.go - 重写 ProcessEventBatch
func (e *Engine) ProcessEventBatch(events []*dto.Payload, api openapi.OpenAPI) {
    // 1. 收集所有需要的事件类型
    // 2. 检查排序缓存
    // 3. 如果缓存未命中，升级锁并排序
    // 4. 使用排序缓存处理每个事件
    
    // 关键：使用 sortedCache 而不是 matcherIndex
    sortedCache := make(map[dto.EventType][]*Matcher)
    // ...复制缓存或触发排序...
    
    for _, event := range events {
        specificMatchers := sortedCache[eventType]
        genericMatchers := sortedCache[""]
        // 归并排序并执行
    }
}
```

**代码修改:**
- `engine.go`: 完全重写 ProcessEventBatch 方法（~70 行）

**测试:**
- `engine_batch_sorted_test.go`: 10 个测试用例
- 测试排序一致性、混合事件类型、缓存构建

**用户影响:**
- **行为一致**: ProcessEvent 和 ProcessEventBatch 现在行为一致
- **性能**: 利用排序缓存，减少排序开销

### 5️⃣ #8 - 规则缓存无限增长 ✅

**问题描述:**
- 正则表达式缓存使用 `sync.Map`，没有容量限制
- 恶意用户可能通过大量不同的正则触发内存耗尽
- 潜在的 DoS 攻击向量

**解决方案:**
```go
// rules.go - 实现 LRU 缓存
type regexCacheStore struct {
    mu       sync.RWMutex
    cache    map[string]*regexCacheEntry
    lruList  []string
    maxSize  int  // 默认 1000
}

type regexCacheEntry struct {
    re         *regexp.Regexp
    lastAccess time.Time
}

// 淘汰策略：删除最旧的条目
func (rc *regexCacheStore) evictOldest() {
    // 找到最旧的条目并删除
}

// 新增配置方法
func SetRegexCacheMaxSize(size int) {
    // 允许用户调整缓存大小
}
```

**代码修改:**
- `rules.go`: 重写缓存机制（~150 行）
  - regexCacheStore 结构
  - LRU 淘汰策略
  - 更新 OnRegex 和 OnRegexSafe
  - 更新 ClearRegexCache 等辅助方法

**测试:**
- `rules_cache_test.go`: 17 个测试用例
- 测试 LRU 淘汰、并发安全、容量限制

**用户影响:**
- **防止 DoS**: 缓存最多 1000 个正则（可配置）
- **自动淘汰**: LRU 策略自动清理
- **向后兼容**: 缓存行为对用户透明
