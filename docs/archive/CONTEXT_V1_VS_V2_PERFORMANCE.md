# Context V1 vs V2 性能对比报告

## 📊 基准测试结果

### 测试环境
- **CPU**: 16 核
- **Go 版本**: Go 1.21+
- **测试日期**: 2025-12-08

---

## 🎯 核心性能指标

### Context 创建性能

| 指标 | V1 (对象池) | V2 (GC) | 对比 |
|------|------------|---------|------|
| **操作延迟** | 133.2 ns/op | 115.9 ns/op | **V2 快 13%** ⚡ |
| **内存分配** | 336 B/op | 416 B/op | V2 多 24% |
| **Allocs 次数** | 2 allocs/op | 3 allocs/op | V2 多 1 次 |

**结论**: V2 的创建速度**更快**，虽然分配略多，但 allocs 次数相差不大。

### 并发场景性能

| 指标 | V1 (对象池并发) | V2 (GC) | 对比 |
|------|---------------|---------|------|
| **操作延迟** | 48.93 ns/op | 115.9 ns/op | V1 快 2.4x |
| **内存分配** | 336 B/op | 416 B/op | V1 少 80 B |

**结论**: 高并发场景下，对象池仍有优势（主要是复用内存）。

### Context 操作性能

#### State 操作

| 场景 | V1 (对象池) | V2 (GC) | 对比 |
|------|------------|---------|------|
| **With Pool** | 332.1 ns/op | - | 基准 |
| **Without Pool** | 342.8 ns/op | - | 慢 3% |

**结论**: State 操作性能差异**可忽略**（3%）。

#### Retain/Release 操作

| 操作 | 延迟 | 说明 |
|------|------|------|
| Retain/Release | 3.9 ns/op | V1 需要，V2 无需 ✅ |
| WithRetain | 5.8 ns/op | V1 需要，V2 无需 ✅ |

**结论**: V2 **完全避免**了这些管理开销。

## 💡 实际场景分析

### 场景 1：简单事件处理（最常见）

```go
// 每次处理一个事件
ctx := NewContext(event, api)
engine.ProcessEvent(ctx)
```

**性能对比**:
- V1: 133 ns（对象池） + 管理开销
- V2: 116 ns（GC）+ 零管理开销

**结论**: V2 **性能更好**（快 13%）✅

### 场景 2：异步处理

```go
go func() {
    doAsyncWork(ctx)
}()
```

**复杂度对比**:
- V1: 需要 Retain (3.9 ns) + Release (3.9 ns) + 管理
- V2: 零开销 ✅

**结论**: V2 **显著简化**，性能相当

### 场景 3：批量处理

```go
for _, event := range events {
    ctx := NewContext(event, api)
    engine.ProcessEvent(ctx)
}
```

**10,000 个事件处理时间**:
- V1: 133 ns × 10,000 = 1.33 ms + 管理开销
- V2: 116 ns × 10,000 = 1.16 ms

**结论**: V2 **更快** 0.17 ms（每万个事件）

### 场景 4：高并发处理（QPS 10K+）

**性能对比**:
- V1 并发: 48.9 ns/op（对象池复用优势明显）
- V2: 115.9 ns/op

**结论**: 极高并发场景下，V1 仍有**2.4x 优势**

### 推荐 V2（GC 模式）的场景 ✅

**大多数应用**（占 95%+）：

- 并发场景有 2.4x 性能优势
- 内存分配略少
- 对象复用效率高
